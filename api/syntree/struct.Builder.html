pub struct Builder<T, F = FlavorDefault>
where
    T: Copy,
    F: Flavor,
{ /* private fields */ }
Expand description

A builder for a Tree.

This maintains a stack of nodes being built which has to be balanced with calls to Builder::open and Builder::close.

§Type parameters and bounds

The two type parameters of the builder determine the following properties:

  • T is the data stored in the tree.
  • F is the Flavor, declared with flavor!. Its Index determines the numerical bounds of spans, and if set to Empty the tree does not store any spans. Its Width determines the bounds of pointers in the tree, which decides how many nodes can be stored in it. It also selects the Storage used and its error type.

To use the default values, use the Builder::new constructor.

§Errors

Besides the errors documented on each method, any method which adds a node or token can fail with Error::Flavor if the flavor’s storage fails to grow.

§Examples

let mut tree = syntree::Builder::new();

tree.open("root")?;
tree.open("child")?;
tree.close()?;
tree.open("child")?;
tree.close()?;
tree.close()?;

let tree = tree.build()?;

let expected = syntree::tree! {
    "root" => {
        "child" => {},
        "child" => {}
    }
};

assert_eq!(tree, expected);

pub fn with_capacity(tokens: usize) -> Result<Self, Error<F::Error>>

Construct a new builder with capacity for tokens tokens.

Every call to Builder::token (and its variants) adds one token, and a token with an explicit span which leaves a gap after the previous token takes one more entry. Interior nodes, added by Builder::open and Builder::close_at, are sized separately through Builder::with_capacities.

§Errors

Errors with Error::Flavor if the flavor’s storage can’t hold tokens tokens.

§Examples
use syntree::{Builder, FlavorDefault};

let mut tree = Builder::<_, FlavorDefault>::with_capacity(2)?;

tree.open("root")?;
tree.token("token", 5)?;
tree.close()?;

let tree = tree.build()?;
assert_eq!(tree.len(), 2);
assert!(tree.capacity() >= 2);

pub const fn cursor(&self) -> &F::Index

Get a reference to the current cursor position of the syntax tree.

The cursor position is the position in which it’s been advanced so far as a result of calls to Builder::token and indicates the current starting index of the next span.

§Examples
let mut tree = syntree::Builder::new();

assert_eq!(*tree.cursor(), 0);
tree.open("child")?;
assert_eq!(*tree.cursor(), 0);
tree.token("lit", 4)?;
assert_eq!(*tree.cursor(), 4);
tree.close()?;
assert_eq!(*tree.cursor(), 4);

let tree = tree.build()?;

let expected = syntree::tree! {
    "child" => {
        ("lit", 4)
    }
};

assert_eq!(tree, expected);

pub fn set_cursor(&mut self, cursor: F::Index)

Set the cursor position of the syntax tree.

This is used to implicitly set spans when using spanless constructions methods. Range queries such as Tree::node_with_range assume that tokens are added in non-decreasing order, so the cursor should not be moved backwards past an already added token.

§Examples
use syntree::Span;

let mut tree = syntree::Builder::new();

tree.open("child")?;
tree.token("lit", 4)?;
// Skip two units of input which are not part of the tree.
tree.set_cursor(6);
assert_eq!(*tree.cursor(), 6);
tree.token("lit", 2)?;
tree.close()?;

let tree = tree.build()?;

let child = tree.first().ok_or("missing child")?;
assert_eq!(child.span(), &Span::new(0, 8));

let spans = child.children().map(|n| n.span()).collect::<Vec<_>>();
assert_eq!(spans, [Span::new(0, 4), Span::new(6, 8)]);

This pushes a new link with the given type onto the stack which links itself onto the last sibling node that was introduced either through Builder::close, Builder::close_at, or Builder::close_at_with.

pub fn open_with( &mut self, data: T, span: Span<F::Index>, ) -> Result<F::Pointer, Error<F::Error>>

Start a node with the given data and span.

This pushes a new link with the given type onto the stack which links itself onto the last sibling node that was introduced either through Builder::close, Builder::close_at or Builder::close_at_with.

pub fn token_with( &mut self, value: T, span: Span<F::Index>, ) -> Result<F::Pointer, Error<F::Error>>

Insert a token with a custom span.

The span is joined into the spans of the enclosing nodes and the tree. Tokens are stored in source order, so a token can’t start before the end of the previous one, but it may leave a gap after it.

§Errors

Errors with Error::Overflow in case we run out of token identifiers, or Error::TokenOrder if span starts before the end of the previous token or ends before it starts.

§Examples
use syntree::Span;

let mut tree = syntree::Builder::new();

tree.open_with("child", Span::new(0, 10))?;
tree.token_with("lit", Span::new(2, 4))?;
tree.token_with("lit2", Span::new(4, 6))?;
tree.close()?;

let tree = tree.build()?;

let child = tree.first().ok_or("missing child")?;
assert_eq!(child.span(), &Span::new(0, 10));

let spans = child.children().map(|n| (n.value(), n.span())).collect::<Vec<_>>();
assert_eq!(spans, [("lit", Span::new(2, 4)), ("lit2", Span::new(4, 6))]);

assert_eq!(tree.span(), &Span::new(0, 10));

Tokens with spans forces the cursor to be set to the end of the span.

use syntree::Span;

let mut tree = syntree::Builder::new();

tree.open("child")?;
tree.token_with("lit", Span::new(2, 4))?;
tree.token_with("lit2", Span::new(4, 6))?;
assert_eq!(*tree.cursor(), 6);
tree.token("lit3", 6)?;
tree.close()?;

let tree = tree.build()?;

let child = tree.first().ok_or("missing child")?;
assert_eq!(child.span(), &Span::new(0, 12));

let lit3 = child.last().ok_or("missing lit3")?;
assert_eq!(lit3.value(), "lit3");
assert_eq!(lit3.span(), &Span::new(6, 12));

assert_eq!(tree.span(), &Span::new(0, 12));

pub fn trivia( &mut self, value: T, len: F::Length, ) -> Result<F::Pointer, Error<F::Error>>

Insert a trivia token with the given length, such as whitespace or a comment.

Trivia is stored like any other token, so the spans of the enclosing nodes and of the tree cover it and the source round-trips losslessly. It is only hidden from iteration: Node::children, Node::walk and the other iterators skip trivia unless asked to include it with with_trivia(). Point accessors such as Node::first or Token::next are structural and do see it. Use Token::is_trivia to tell it apart.

§Errors

Errors like Builder::token.

§Examples
let mut tree = syntree::Builder::new();

tree.open("call")?;
tree.token("ident", 3)?;
tree.trivia("whitespace", 1)?;
tree.token("paren", 2)?;
tree.close()?;

let tree = tree.build()?;

let call = tree.first().and_then(|e| e.into_node()).ok_or("missing call")?;
assert_eq!(call.span(), &syntree::Span::new(0, 6));

let kinds = call.children().map(|e| e.value()).collect::<Vec<_>>();
assert_eq!(kinds, ["ident", "paren"]);

let kinds = call.children().with_trivia().map(|e| e.value()).collect::<Vec<_>>();
assert_eq!(kinds, ["ident", "whitespace", "paren"]);

pub fn close_at( &mut self, c: Checkpoint<F::Pointer>, data: T, ) -> Result<F::Pointer, Error<F::Error>>

Insert a node that wraps from the given checkpointed location.

§Errors

The checkpoint being closed must be a sibling. Otherwise a Error::CloseAtError will be raised.

A checkpoint this builder did not hand out raises Error::MissingCheckpoint.

§Examples
let mut tree = syntree::Builder::new();

let c = tree.checkpoint()?;
tree.token("lit", 3)?;
tree.close_at(c, "root")?;

let tree = tree.build()?;

let expected = syntree::tree! {
    "root" => {
        ("lit", 3)
    }
};

assert_eq!(tree, expected);

More complex example:

let mut tree = syntree::Builder::new();

let c = tree.checkpoint()?;

tree.open("number")?;
tree.token("lit", 3)?;
tree.close()?;

tree.token("whitespace", 1)?;

tree.open("number")?;
tree.token("lit", 2)?;
tree.close()?;

tree.close_at(c, "root")?;

let tree = tree.build()?;

let expected = syntree::tree! {
    "root" => {
        "number" => {
            ("lit", 3)
        },
        ("whitespace", 1),
        "number" => {
            ("lit", 2)
        },
    }
};

assert_eq!(tree, expected);

Adding a token after a checkpoint:

let mut tree = syntree::Builder::new();

let c = tree.checkpoint()?;
tree.open("child")?;
tree.token("lit", 3)?;
tree.close()?;
tree.close_at(c, "root")?;
tree.token("sibling", 3)?;

let tree = tree.build()?;

let lit = tree.node_with_range(0..3).ok_or("missing at 0..3")?;
assert_eq!(lit.value(), "lit");

let child = lit.parent().ok_or("missing child")?;
assert_eq!(child.value(), "child");

let root = lit.ancestors().last().ok_or("missing root")?;
assert_eq!(root.value(), "root");
assert_eq!(root.parent(), None);

let expected = syntree::tree! {
    "root" => {
        "child" => {
            ("lit", 3)
        }
    },
    ("sibling", 3)
};

assert_eq!(tree, expected);

pub fn build(self) -> Result<Tree<T, F>, Error<F::Error>>

Build a Tree from the current state of the builder.

§Errors

This requires the stack in the builder to be empty. Otherwise a Error::BuildError will be raised.

§Examples
let mut tree = syntree::Builder::new();

tree.open("child")?;
tree.token("number", 3)?;
tree.close()?;
tree.open("child")?;
tree.close()?;

let tree = tree.build()?;

let expected = syntree::tree! {
    "child" => {
        ("number", 3)
    },
    "child" => {},
};

assert_eq!(tree, expected);

If a tree is unbalanced during construction, building will fail with an error:

use syntree::{Error, Span, Builder};

let mut tree = syntree::Builder::new();

tree.open("number")?;
tree.token("lit", 3)?;
tree.close()?;

tree.open("number")?;

// "number" is left open.
assert!(matches!(tree.build(), Err(Error::BuildError)));
