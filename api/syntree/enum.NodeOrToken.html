Enum NodeOrToken 

Source 
pub enum NodeOrToken<N, K> {
    Node(N),
    Token(K),
}
Expand description

Either a node or a token.

Iterators which visit both nodes and tokens yield the Element instance of this. Its Debug output is that of the node or token it holds.

pub fn find_preceding<P>(&self, predicate: P) -> Option<Element<'a, T, F>>
where P: FnMut(Element<'a, T, F>) -> bool,

Find a preceding element which matches the given predicate.

A “preceding element” is one whose tokens immediately precede the tokens of the current element. This is found in two steps:

  1. Starting with the current element and moving through its ancestors, find the first prev sibling which matches the predicate.
  2. From that sibling, descend through last children for as long as each matches the predicate, and return the last match.

Step 2 stops at the first last child which does not match, so a matching element nested below a non-matching last child is not found.

§Examples
let tree = syntree::tree! {
    "root" => {
        "child1" => {
            ("token2", 1),
            "child2" => {
                ("token1", 2)
            }
        },
        "child3" => {
            "child4" => {
                ("token1", 4),
            }
        }
    }
};

let node = tree.node_with_range(3..3).ok_or("missing 3")?;
assert_eq!(node.value(), "token1");

let found = node.find_preceding(|n| n.span().end == 3 && n.has_children());
let found = found.ok_or("expected preceding node")?;
assert_eq!(found.value(), "child2");
